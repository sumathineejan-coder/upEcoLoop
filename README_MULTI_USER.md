# EcoLoop — ระบบสมาชิกและฐานข้อมูลหลายผู้ใช้

## ความสามารถ
- หน้าแนะนำโครงการก่อนเข้าสู่ระบบ ใช้โทนสีเขียว–ครีมตามอัตลักษณ์ EcoLoop
- สมัครสมาชิกและเข้าสู่ระบบแยกบทบาทนักศึกษา/ร้านค้า
- ฐานข้อมูล SQLite กลางบนเซิร์ฟเวอร์ เก็บบัญชีผู้ใช้แบบ hash รหัสผ่าน, session, รหัสยืนยัน และประวัติรายการ
- นักศึกษาสร้างรหัสยืนยัน 6 หลัก อายุ 60 วินาที ใช้ได้ครั้งเดียว
- ร้านค้าตรวจสอบรหัสและยืนยันเมื่อเห็นการใช้แก้วส่วนตัวจริง จึงบันทึก 100 Eco Points
- ผู้ใช้แต่ละบัญชีเห็นเฉพาะข้อมูลที่เกี่ยวข้องกับตนเอง
- รองรับการเข้าใช้งานจากหลายอุปกรณ์เมื่อเว็บไซต์เผยแพร่บนเซิร์ฟเวอร์เดียวกันที่มีฐานข้อมูลกลางและพื้นที่จัดเก็บถาวร

## ข้อกำหนดสำคัญเรื่องการเผยแพร่
**GitHub Pages ไม่สามารถรัน Node.js/Express หรือเก็บฐานข้อมูล SQLite ฝั่งเซิร์ฟเวอร์ได้** ดังนั้นการนำเว็บ static ไปไว้บน GitHub Pages อย่างเดียวจะไม่ทำให้ระบบล็อกอินหลายเครื่องทำงาน

ไฟล์ `render.yaml` เตรียมการตั้งค่า Render Web Service พร้อม Persistent Disk ไว้ให้แล้ว:
1. อัปโหลดโฟลเดอร์ `ecoloop_work` ไปยัง GitHub repository
2. เข้า Render แล้วเลือก New > Blueprint และเชื่อม repository
3. Render จะอ่าน `render.yaml` และสร้าง Node service พร้อม disk ที่ `/var/data`
4. เมื่อ deploy สำเร็จ ให้ใช้ URL ของ Render เป็น URL หลักของเว็บไซต์ ไม่ใช่ GitHub Pages
5. ตั้งค่า `NODE_ENV=production` และ `DATA_DIR=/var/data` ตามไฟล์ Blueprint
6. ทดสอบสมัครบัญชีนักศึกษาจากอุปกรณ์หนึ่ง แล้วเข้าสู่ระบบบัญชีเดิมจากอีกอุปกรณ์หนึ่ง

หมายเหตุ: Render Persistent Disk เป็นบริการแบบมีค่าใช้จ่ายตามแพ็กเกจ/เงื่อนไขของผู้ให้บริการ ควรตรวจสอบราคาและข้อจำกัดล่าสุดก่อนเปิดใช้งานจริง หากใช้โฮสต์อื่น ต้องกำหนด persistent volume ให้ `DATA_DIR` เช่นกัน และควรรันแอปเพียงหนึ่ง instance สำหรับ SQLite

## รันในเครื่องเพื่อทดสอบ
ต้องติดตั้ง Node.js 20 ขึ้นไป:
```bash
npm install
npm start
```
เปิด `http://localhost:3000`

## รูปแบบบัญชี
- รหัสบัญชี: ตัวเลข 5–20 หลัก
- รหัสผ่าน: อย่างน้อย 6 ตัวอักษร (แนะนำให้ใช้รหัสผ่านที่คาดเดายาก)
- รหัสเดียวกันสามารถสมัครได้หนึ่งบัญชีต่อหนึ่งบทบาท (นักศึกษา/ร้านค้า)

## ข้อความและความถูกต้องของข้อมูล
- ค่า CO₂e เป็นค่าประมาณตามสมมติฐาน 20 กรัมต่อรายการ ไม่ใช่คาร์บอนเครดิตที่ได้รับการรับรอง
- Smart Insight เป็นการวิเคราะห์ตามเงื่อนไข (rule-based) ไม่ใช่โมเดล Generative AI
- ระบบยืนยันรหัสช่วยบันทึกการตรวจสอบ แต่การยืนยันว่าเห็นการใช้แก้วจริงยังต้องอาศัยการตรวจสอบของพนักงานร้านค้า

## โครงสร้างหลัก
- `server.js` — API, การยืนยันตัวตน และการจัดการข้อมูล
- `public/index.html` — เว็บไซต์
- `data/` — ฐานข้อมูลในเครื่องทดสอบ (ไม่ควร commit ฐานข้อมูลจริง)
- `render.yaml` — ตัวอย่างการ deploy พร้อม persistent disk
